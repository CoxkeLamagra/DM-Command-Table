# Operability and resource refactor — 2026-11-18

Release v12.1.5 starts from v12.1.4 (`45515c0`). It changes internal operational code and tests. No visual components, user workflows, permissions, API formats, storage schema, runtime paths or deployment settings are changed. The fixed GUI-update socket and its start/status protocol remain in place. Release preparation also updates the framework patch and guards development pattern compilation as described below. No live host is changed.

## Changes and resource evidence

Backups hold the SQLite write reservation through the consistent database snapshot and all referenced media copies. The completed private copy is then independent of live changes, so the reservation and connections close before hashes, manifest creation and verification. Normal application writes can resume during those later phases. The regression test proves writes fail during copying, succeed during hashing, and that deleting/changing live data at that point does not invalidate the backup's original database/image contents.

Checksum passes reuse a 64 KiB scratch buffer. A local fixture with 32 recorded images compared the v12.1.4 implementation against this change: creating and verifying the backup allocated 66 such buffers before and two afterward (4,325,376 versus 131,072 cumulative scratch bytes). Both backups subsequently verified all 32 files. These numbers describe cumulative scratch allocations, not peak memory or overall backup-speed guarantees. Files are still copied and independently verified; hashing is not skipped.

Partial backup directories are removed if opening the source connection fails. Rollback/cleanup failures retain the original error in an aggregate diagnostic and still attempt cleanup. Backup/manifest/restore formats are unchanged. Verification checks the first foreign-key violation without allocating all violation rows; the standalone storage checker now checks foreign keys too.

Updater transport uses a stateful UTF-8 decoder and counts received bytes against the existing 512 KiB ceiling. A total five-second deadline covers connection and response time; activity cannot prolong it indefinitely. Response parsing, size errors, disconnects and completion share timer/socket cleanup. Missing services still produce an unavailable status; start requests still fail when the service is absent. This repairs transport handling without changing broker authority or adding settings.

Maintenance excludes campaign-referenced files in SQL instead of materializing all reference IDs, prepares its history/deletion statements once, and iterates known filenames without a duplicate row array. Undo-history matching and the 24-hour staging/unmatched-file rules are retained. Existing quarantine files are preserved by assigning a UUID prefix to colliding new copies. Missing database paths fail before creating storage. A failure rolls back SQL changes and attempts to restore every moved file, reporting incomplete restoration rather than hiding the original error. The command's successful JSON output remains `{ "quarantined": count }`.

## Validation

Formatting, ESLint, TypeScript, all **175 unit/integration tests**, the production build and all **21 browser regressions** passed. New tests exercise real Unix sockets with split Unicode, persistent partial traffic, oversized/malformed/truncated frames and absent services; backup write contention, live-data independence and source-open failure cleanup; foreign-key corruption; protected/expired media, quarantine collisions, maintenance idempotence, rollback after an injected deletion failure and missing database paths. Existing browser tests cover unchanged user/admin workflows and navigation. A packaged-runtime smoke check also verified readiness, manifest integrity and the standalone backup, verify, restore, maintenance and storage commands against disposable empty storage; media behavior is covered by the separate backup/maintenance fixtures.

The focused backup test temporarily intercepts filesystem calls within its isolated test process to inspect lock state at copy/hash boundaries. All data is disposable. No production credentials, live-site checks, real systemd installation or Docker deployment are involved. The refactor is not a completed Codex Security scan or a vulnerability-free certification.

## Release dependency remediation

The release pins Next.js and its matching lint configuration to **16.4.6**, addressing GHSA-mfr8-8qww-v76h and GHSA-vc7v-qv4w-wrv8 (reported patched range begins at 16.4.5). Both packages were published on 2026-11-09, so they exceed the existing seven-day age policy on the release date. Frozen installation still enforces all package-age and supply-chain checks.

GHSA-fc5q-39xc-vjpf affects development-only picomatch 2.3.2 and 4.0.4 in the ESLint/fast-glob/micromatch and resolver/TypeScript ESLint/tinyglobby/fdir chains. No fixed npm release was available during preparation. Two small pnpm patches explicitly reject positive repeated extglobs and raw unbounded regex-repeat spellings before compilation. They throw `SyntaxError`; unsafe input is not silently reinterpreted. Options such as disabling the existing recursion guard cannot disable the new checks. This deliberately makes repeated extglob/raw-repeat syntax unavailable to these development dependencies. The repository does not use it, and the full lint/build/browser workflows remain supported. Ordinary wildcards, brace patterns, character classes, negative/optional/@ extglobs and quoted/escaped literals remain supported. No application code imports the glob libraries.

The audit gate walks every installed dependency path reported for this advisory and validates the actual modules, rather than trusting a version number or patch filename. Only this exact advisory, these two versions and development-only findings qualify. Tests cover the original patterns, ambiguous literal alternatives, nested/wrapped forms, raw regex aliases, multiple options, ordinary controls and bounded subprocess execution. Production copies, other versions, unrelated findings and registry failures still block. The raw registry advisory remains open; it is a locally verified mitigation, not a zero-advisory raw audit or an upstream resolution. The existing braces patch policy remains unchanged.

An independent read-only review identified three regex aliases missed by the first candidate. The final patch covers them and the focused regressions exercise them. Independent follow-up review was unavailable; the final delta received a separate author source review and runtime regression checks. Caller-supplied precompiled regex state and direct `RegExp` interfaces remain trusted-code APIs outside this string-pattern guard. The changes do not claim to make arbitrary regular expressions or all glob workloads linear-time.

After remediation, `pnpm verify`, **177 unit/integration tests**, **21 browser tests**, runtime packaging and the packaged operational smoke checks pass. This is checkout validation, not live deployment. Keep monitoring the upstream picomatch advisory and replace the local guard with a reviewed compatible upstream fix when available; the audit must remain enabled for future releases.
